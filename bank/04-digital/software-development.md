# قرارداد توسعه نرم‌افزار

> **یادآوری مهم:** این متن یک الگوی عمومی و اولیه برای تدوین سند است، نه مشاوره حقوقی و نه تضمین اعتبار یا کفایت برای هر پرونده. پیش از امضا، متن را با قوانین لازم‌الاجرا، مدارک واقعی، شرایط معامله و وضعیت طرفین تطبیق دهید. جاهای داخل [کروشه] باید تکمیل و بندهای نامرتبط حذف یا اصلاح شوند.

**شناسه:** DG-001 · **دسته:** فناوری و نرم‌افزار

کارفرما [ ] و توسعه‌دهنده/شرکت [ ] توافق می‌کنند:

### ۱. دامنه پروژه
شرح محصول، نقش‌های کاربری، پلتفرم‌ها، قابلیت‌ها، محدودیت‌ها و موارد خارج از دامنه در سند نیازمندی‌ها پیوست می‌شود. عنوان کلی «ساخت نرم‌افزار» به‌تنهایی معیار کافی پذیرش نیست.

### ۲. مراحل و تحویل
تحلیل [ ]؛ طراحی [ ]؛ نمونه اولیه [ ]؛ توسعه [ ]؛ آزمون [ ]؛ استقرار [ ]؛ آموزش [ ]. برای هر مرحله، خروجی، مهلت و معیار پذیرش تعیین شود.

### ۳. مبلغ و تغییرات
مبلغ و زمان پرداخت [ ]؛ هزینه میزبانی/مجوزهای ثالث [ ]؛ درخواست تغییر دامنه باید شامل اثر بر قیمت، زمان و ریسک باشد.

### ۴. کد و مالکیت فکری
مالکیت کد سفارشی، مخازن، مستندات، کتابخانه‌های از پیش موجود، اجزای متن‌باز و مجوزهای ثالث به‌طور جداگانه تعیین شود. دسترسی مخزن، تحویل کد منبع و زمان انتقال حقوق [ ].

### ۵. داده و امنیت
مالک داده، سطح دسترسی، پشتیبان‌گیری، رمزنگاری، ثبت رخداد، نگهداری و حذف داده، مدیریت رخداد امنیتی و مسئولیت افشای اطلاعات [ ].

### ۶. آزمون و پذیرش
محیط آزمون، سناریوها، سطح خطاهای مانع انتشار، مهلت گزارش ایراد و مدت رفع نقص [ ]. تغییرات پس از پذیرش با پشتیبانی/توسعه جدید تفکیک شوند.

### ۷. میزبانی و پشتیبانی
محل میزبانی، دسترس‌پذیری مورد انتظار، مسئول دامنه و گواهی، هزینه‌های جاری، سطح پشتیبانی و زمان پاسخ [ ].

### ۸. تعلیق و خاتمه
تحویل آخرین نسخه، خروجی پایگاه داده، انتقال دسترسی‌ها، تسویه و حذف دسترسی غیرضروری [ ].

### ۹. پیوست‌ها
سند نیازمندی‌ها، معماری، برنامه زمان‌بندی، سیاست امنیت و جدول هزینه‌های جاری.
